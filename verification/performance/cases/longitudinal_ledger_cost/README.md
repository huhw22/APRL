# 当前高阶程序：能量诊断增量成本

用户询问本轮账本占多少时间。本测试只测已构建的高阶程序，不修改推进、默认入口或运行中的全量19261/19262。

程序固定为 `build/longitudinal-main-flow-r1-20261103/aprl`，SHA256 `c693d067153934ea5b683305bff5d5be27284cd065396aa0cd11181c392720d0`。基准为已完成主流程短漂移卡：同一输入31675记录、同一网格、释放、Cowan、五次源/取场、子步、固定点容差、原始场/粒子探测面、停止规则和输出频率。一独占128CPU节点，16 MPI×8线程，无节点约束；profiling关闭。

四组配置只有输出路径及以下诊断差异：

| 模式 | 普通boost账本 | 严格场算子审计 | 两个lab能量面 |
|---|---|---|---|
| off | 关 | 关 | 关 |
| basic | 开 | 关 | 关 |
| strict | 开 | 开 | 关 |
| all | 开 | 开 | 开 |

普通账本采样／写出间隔10步、lab能量面buffer64，与本轮生产设置一致。严格审计按每一步记录原更新的离散通道；普通账本的10步采样不会使严格审计变为每10步才计算。

按off/basic/strict/all、all/strict/basic/off的正反顺序各跑一次。所有工况完整结束后读取H5，并要求共同的原始E/B、粒子面与时间轴逐位一致。关闭账本仍保留算法自身的平均速度求解、固定点功残差、必要缓存与收敛检查。这些是当前推进算法的成本，不能视为关闭诊断即可省掉的账本。

统一使用80—160步的推进秒／步；已闭合普通账本确认此区间31675粒子全部释放且尚无移除。排除初始化、最终关闭、离线H5核对的耗时，不使用含Slurm启动的总墙钟。

对每次重复，记四组秒／步为T0、T1、T2、T3：

- 普通账本增量：T1−T0。
- 严格审计增量：T2−T1。
- lab能量面增量：T3−T2。
- 全部诊断可省时间：T3−T0。
- 诊断占全开推进时间的份额：(T3−T0)/T3。
- 开启诊断相对关闭版的增幅：(T3−T0)/T0。

两个百分比的分母不同，不能混称。分项占比都使用同次重复的T3，不能各用各自分母。保留两次原值及范围，不裁掉负的噪声增量，不据两个样本拟合置信区间。小工况的粒子/场比例与全量不同，不能把短测份额直接宣布为4.5 m或0.5 m完整大仿真的精确份额。

运行目录：`results/longitudinal_ledger_cost_20261103/r1`。冻结输入在FROZEN.json，逐组日志/绑定/闭合与BITWISE.json、最终RESULT.json和COST.csv是证据。只读已闭合H5，不读运行中全量输出。
