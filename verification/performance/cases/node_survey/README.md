# gnode1 CPU 小测试的运行前检查

2026-10-24（Asia/Shanghai）只读检查找到一台 `gnode1`，地址 `10.10.10.11`。用户随后说明可能只有这一台，不再假定存在 `gnode2`。

已确认的环境：

- 双路 AMD EPYC 7261，每路8个物理核；合计16物理核、32个SMT逻辑线程。
- 8个NUMA域，每域2个物理核；首次布局比较按16个物理核预算，不能把32逻辑线程当成32物理核。
- 系统可见内存约126 GiB，检查时可用约124 GiB，负载接近零。这是当时快照，不是资源预约。
- Ubuntu20.04、Open MPI4.0.3；共享工作区、候选和基线可读，动态库符号检查及Python依赖导入通过。
- 当前Slurm只有 `ssmb` 分区的 `node1`–`node8`；`gnode1` 未注册，节点上也没有可用的Slurm运行入口。

证据在工作区 `results/node_survey/inspection-20261023T175137Z/`。本次只读调查没有运行MPI探针或科学模拟。

## 运行约束

根目录 `AGENTS.md` 要求“计算作业通过 Slurm 提交到计算节点”。因此，这个独立探针只有在用户明确允许 **gnode1 通过SSH直接运行CPU测试** 后才能执行。当前准备脚本不表示已获得该例外授权。

`cpu-preflight.sh --plan` 仅展示计划。`--run` 额外要求 `APRL_ALLOW_UNSCHEDULED_CPU_TESTS=1`，必须位于gnode1，检查负载并用本工作区锁避免重复启动。该锁不能预约其他用户的CPU，也不能替代调度器的资源隔离。脚本只运行绑核探针，不运行粒子仿真，不使用GPU，不更改MPI网络配置。

四组布局为16×1、8×2、4×4、2×8，每组16物理核、限时60秒。探针核实rank数、线程数、实际亲和性，以及所有线程是否占用不同物理核。SMT兄弟逻辑CPU可以属于同一线程的亲和性集合，但不能被计作额外物理核。4线程和8线程布局会涉及多个NUMA域，需记录实际拓扑。

独立探针源码派生自验收探针，仅调整无Slurm模式的显式运行授权与主机限制；原验收探针和历史冻结清单保持不变。编译产物放 `build/node-survey/`，工作副本和独立清单放 `tests/node_survey/`。实际结果总是创建新的 `results/node_survey/` 子目录。

## 后续经验规则的范围

先通过绑定及小型科学输出检查，再使用若干独立、固定的通用Gaussian卡改变工作量类别（网格较多、粒子较多、综合），每张卡在不同布局间完全相同。关闭profiling的重复时间用于选布局；分项计时仅用于解释。经验规则应考虑网格单元数、最忙rank的粒子数、线程数和NUMA分布，并用未参与拟合的测试验证误差。

gnode1可以用于单节点MPI/OpenMP取舍的标定；它和128核EPYC7742节点的拓扑不同，系数及最优布局不能直接移植。只有一台gnode1时，无法实测跨节点通信的扩展规律；多节点系数需待至少两台同类机器可用后另行验证。
