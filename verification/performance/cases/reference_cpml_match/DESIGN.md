# 参考初场与横向CPML匹配：授权方案与验收

用户明确允许边缘区域向数值边界关系妥协，优先维持内部粒子空间电荷动力学。
第一方案在mesh.moving_window增加reference_through_cpml（默认false）。启用时
只把快速参考求解与场构造的横向guard从CPML内缘改到已有网格最外端：在CPML
里也构造参考E/B，有限零势面与原外层PEC终止面对齐。活动窗口、dx/dz/dt、
Cowan/Boris/沉积/CPML更新、粒子释放事件均保持，不新增电流或能量源项。
静态Poisson内部从139²变159²，准备成本略增；每步活动场网格不变。

这不是宣称普通CPML自动与任意准静态场匹配。CPML内初场及零初始历史可能
仍有调整，必须看传播足够时间之后的平均纵向动量、内部膨胀、能量变化与
能散。不要只凭首步脉冲小就宣称整个模拟物理验收。

测试顺序：同工具链独立binary；77required；关闭选项100步与上一已验binary
18个H5科学records逐位；同uniform输入500步pilot，开启原严格能量账本和
只读实际E/B冲量探针；原核单步接口检查。若有明确改善，再用完整短uniform、
converging、gaussian及固定MPI总数双节点短工况验收，而非启动实际41M生产。

理论比较继续按各粒子相同事件与共同boost时间完整cohort两套口径。
无新能量源，所以原v5账本和原离散算子账本保持并核对。
程序默认、cluster.env、原数据和运行中冻结脚本保持；失败尝试独立存档。

参考资料：Meep官方PML文档说明吸收区需与源/近场相容，不能由传播波反射率
推断所有准静态情形；本文将其作为方法背景，不把文献中的波导情形直接当成
本粒子束问题的结论。
https://meep.readthedocs.io/en/latest/Perfectly_Matched_Layer/

https://arxiv.org/pdf/2201.09084 讨论粒子穿越PML时的伪场，和本轮无粒子到达
横向界面的启动问题不同；本轮不引入该文的粒子吸收算法。
