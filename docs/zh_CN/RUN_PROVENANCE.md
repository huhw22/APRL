# 运行身份、清单与覆盖保护

每次启动模拟器时，MPI rank 0 都会在分配场数组之前创建一份 YAML 运行清单，并为本次运行生成唯一的 `run_id`。清单保存原始输入卡全文、其 FNV-1a 配置摘要、源码版本（若配置时工作区有改动则带 `-dirty`）、编译器/构建/HDF5 描述、MPI 实现与 rank 数，以及粒子输入身份。对于大型 HDF5 粒子文件，身份只使用路径、字节数和修改时间，不会在启动时重新读取并散列整个文件。

模拟器生成的每个场面、粒子面、弹道参考、轨迹和能量账本 HDF5 组都写入相同的 `run_id`、配置摘要、源码版本和清单路径。这些属性是判断分散保存的多个文件是否属于同一次运行的权威依据。

```yaml
output:
  overwrite: false
  manifest: output/run-manifest.yaml
```

`overwrite` 默认为 `false`。推进开始前，模拟器会在全部 MPI rank 上检查所有已启用的输出路径；只要清单、任一 rank 轨迹、探测器或账本文件已经存在，就拒绝运行。只有在确认可以整体替换本次运行的全部输出时才设为 `true`。该开关同时作用于本次调用的全部输出，不能逐个文件授权，从而避免无意混合新旧结果。

每个后处理输入卡拥有独立的 `output.overwrite`，同样默认 `false`。后处理器会在所有 YAML 映射层级拒绝未知键，并在禁止覆盖时使用排他方式创建 HDF5。正常分析迭代应使用新的输出文件名；显式覆盖主要用于可丢弃的测试。

清单仅由 rank 0 写入。探测器和能量账本 HDF5 也是 rank 0 独占；轨迹则每个 rank 一个文件，因此运行身份机制不会引入共享 MPI 写入。
